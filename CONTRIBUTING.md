# Contributing Guidlines
Follow so main remains stable

# Branching Strategy
1) main - always stable. Protected: no direct pushes.
2) feature/(short-description) — new features (e.g. feature/login-access).
3) fix/(short-description) — bug fixes (e.g. fix/frozen-page-after-login).
4) docs/(short-description) — changes to any documentation.

Branch off from main, work in your own feature branch, and open a pull request back into main when it is ready.

# Commits
Keep commit messages short but descriptive:
1) Format: (type of change): (short descriptive summary)
2) Types may include: feature, fix, doc, refactor, test, etc
3) Example: feature: add a login form validation system for users

# Pull Requests
1) Push your branch and open a pull request (PR) against main.
2) Fill in the PR description: what is changed and why.
3) Link the related task/issue from the project board.
4) Request review from at least one teammate.
5) Address feedback, then merge once approved and checks pass (squash merge preferred to keep history clean).
6) Delete the branch after merging.

# Project Board
All the work should be tracked on the Jira ChordChitic Developement space.
Before starting anything there should be an issue or card for it.
Make sure to assign yourself or be assigned.
